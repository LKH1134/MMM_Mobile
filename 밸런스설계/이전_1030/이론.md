# 이론 — 방치형 강화 비용·골드 곡선 (로그형 진행)

작성: theory · 재현: `python 밸런스설계/theory/model.py [current|proto|proposal|all]` (난수 없음, 다시 돌리면 같은 값)

## 1. 가정

- 공식 원본: `Assets/Scripts/Mobile/Idle/IdleProgress.cs` (2026-10-30 작업본). `model.py`는 Defs·ExpectedLevel·ExpectedCapped·EnemyCount·Cost를 그대로 옮겼다(int 버림·Ceiling·Round 포함).
- 한 판 = 웨이브 5개 + 보스 1회, **40초 고정**. 판당 골드 = 처치당 골드 × units(s), units = 보스 20 + Σ웨이브 적 수(s≥11이면 95).
- 플레이어는 기대 성장 곡선대로 키운다. R(s) = (스테이지 s→s+1 기대 성장분 비용 합) ÷ 판당 골드. 누적 시간 = Σ 40초 × max(1, R) (보스를 잡아야 넘어가므로 최소 1판).
- 보유 효과(가챠)·오프라인 보상·광고 배수는 빼고 본다(실제 시간은 이보다 짧아진다 → 목표 시간은 여유 있게).

## 2. 왜 골드가 줄어드나 (원인 확인)

| 안 | 골드 감소 지점 (1~1000) | 원인 |
|---|---|---|
| 현재 | **545개** (65 이후 거의 매 홀수 스테이지 + 400 이후 추세 하락) | 비용 ∝ Lv^2.5(다항)인데 나누는 반복 계수는 e^(s/150)(지수) → 결국 역산 골드가 줄어든다. 홀짝 톱니는 Speed `(int)(1.5·s)`가 1·2레벨 번갈아 오르는 것 |
| 관리자 시안 (manager_proto) | **101개** (101, 201, 213, 221, 229 …) | 101: 공격 속도가 Lv 150(최대)에 닿아 그 스테이지부터 성장분에서 빠짐. 213·221·…(8 간격): 상급 공격력 기대 레벨이 1.875/스테이지 = 15/8이라 int 버림으로 8스테이지마다 한 번 +1 대신 +2/+1이 바뀜. e^(Lv/190)으로 상급 공격력 한 레벨이 아주 비싸져 그 한 레벨 차이가 골드를 깎는다 |

**결론**: "골드 = 그 스테이지 성장분 합을 역산"하는 한, 성장분 합은 레벨이 정수라서 생기는 톱니·해금·최대 도달 때문에 **본질적으로 울퉁불퉁**하고, 그 울퉁불퉁이 그대로 처치당 골드 감소로 보인다. 스케일 상수를 아무리 조정해도 0개로 만들기 어렵다(running max 같은 땜질은 가능하지만 구조가 숨는다).

## 3. 고른 구조: 골드 = 독립 함수, 비용이 그보다 가파르게

| | (A) 역산 유지 (지금 방식) | (B) **골드 독립 함수 (고름)** |
|---|---|---|
| 골드 단조성 | 성장분 합의 톱니가 그대로 → 감소 지점 생김 | 식 자체가 단조 → **감소 0 보장** |
| 로그형 진행 | 반복 계수 e^(s/150)을 직접 넣어 정확 | 비용에 e^(Lv/costScale)을 넣어 R ≈ e^(s/150)이 **결과로** 나옴 (오차 ×0.86~1.39) |
| 사용자 의도 ("생산량은 계속 늘고, 소모량이 더 빨리") | 골드가 비용에 종속 — 의도와 반대 방향 설명 | 의도 그대로: 골드 ∝ s^2.5(다항, 계속 증가), 비용 ∝ Lv^2.5 × e^(Lv/scale)(지수) |
| 코드 | 캐시 + 이중 루프 | 한 줄, 캐시 불필요 |
| 단점 | — | 강화 표를 바꾸면 R이 따라 변함(골드가 자동 보정 안 됨) → `model.py`로 R/FarmFactor 확인 필요 |

R의 울퉁불퉁(인접 스테이지 최대 ×1.24)은 "몇 판 더 도느냐"에만 나타나 플레이어 눈에 거의 안 보인다. 처치당 골드 숫자는 보인다 → 단조여야 하는 쪽은 골드다.

## 4. 수치안

### 4.1 비용: `Cost = ceil(costBase × (1 + Lv/10)^costExp × e^(Lv / costScale))`

costScale = FarmScale(150) × (그 강화의 기대 레벨이 스테이지당 오르는 양). 이러면 기대 레벨에서 지수 항이 모든 강화에서 똑같이 e^((s−1)/150)이 되어, 강화별 성장분 비중이 스테이지가 올라도 유지된다(관리자 시안 1/1500 등은 이보다 약 1.5배 가팔라 후반 비중이 상급 강화로 쏠림).

|---|---|---|---|
| 공격력 | 15 | **2250** | 1500 |
| 체력 | 15 | **2250** | 1500 |
| 체력 재생 | 9 | **1350** | 900 |

### 4.2 골드: `EnemyGold(s) = round(GoldBase × (1 + (s−1)/GoldStep)^GoldExp)`

- **GoldBase = 30, GoldStep = 1.5, GoldExp = 2.5**. BossGold = ×20 (그대로).
- 근거: 이론안 비용에서 "R = FarmFactor가 되는 골드"를 계산해 (1.5s)^2.5로 나누면 s=10~1000에서 3.6~5.5 → 큰 s에서 30/1.5^2.5 ≈ 10.9·s^2.5 ≈ 4·(1.5s)^2.5와 일치. 스테이지 1 = 30으로 지금(29)과 같다.
- 단조: 2~2000 모든 s에서 엄격 증가(같은 값 0, 감소 0).

### 4.3 유지하는 것

ExpectedLevel·ExpectedHit·EnemyHp·BossHp·EnemyAttack·BossAttack·EnemyCount·Defs의 다른 값·FarmScale(=150, 이제 costScale 산정 근거로만 쓰임) **변경 없음**. 적 강함은 기대 레벨로만 정해지고 비용·골드와 무관하므로 그대로 둬도 된다.

## 7. 적용안 (관리자)

파일: `Assets/Scripts/Mobile/Idle/IdleProgress.cs`

1) `Def`에 필드 추가 (주석 갱신):
```csharp
public double costBase, costExp;    // 비용 = costBase × (1 + Lv/10)^costExp × e^(Lv/costScale)
public double costScale;            // 0 = 지수 항 없음. = FarmScale × (기대 레벨/스테이지) → 기대 레벨에서 e^((s-1)/FarmScale)
```

2) `Defs`에 `costScale` 추가: Attack 2250, Hp 2250, HpRegen 1350, Speed 0(생략), CritChance 450, CritDamage 338, AdvancedAttack 281, NormalEnemyDamage 141.

3) `Cost(IdleStat stat, int lv)`:
```csharp
public static long Cost(IdleStat stat, int lv)
{
    var d = Get(stat);
    double c = d.costBase * System.Math.Pow(1 + lv / 10.0, d.costExp);
    if (d.costScale > 0) c *= System.Math.Exp(lv / d.costScale);
    return (long)System.Math.Min(9e18, System.Math.Ceiling(c));
}
```

4) 골드: `baseGoldCache`·`BaseEnemyGold` 삭제, `EnemyGold` 교체:
```csharp
// 골드(생산량)는 스테이지의 거듭제곱으로 계속 오르고, 강화 비용(소모량)은 거듭제곱 × 지수(costScale)라 더 빨리 오른다.
// 그 차이 ≈ FarmFactor(s) = e^((s-1)/FarmScale)가 스테이지당 반복 판 수 → 누적 시간 대비 스테이지가 로그 곡선
public const double GoldBase = 30, GoldStep = 1.5, GoldExp = 2.5;
public static long EnemyGold(int stage) =>
    (long)System.Math.Max(1, System.Math.Round(GoldBase * System.Math.Pow(1 + (stage - 1) / GoldStep, GoldExp)));
```
`FarmScale`·`FarmFactor`는 남겨 두면(설명·검증용) 좋다. 다른 파일 참조 없음(`EnemyGold`·`BossGold`만 `IdleBattle.cs:499`에서 사용).

5) `Defs` maxLv: 공격력·체력 100000 → **45000**, 체력 재생 100000 → **28000** (verify#4, 9절). 나머지 강화는 maxLv에서 비용 ≤ 4.9e10~3.5e13이라 그대로.

6) 같이 맞출 곳(관리자 판단): `GameBalance.xlsx`/`GameBalance.bytes` 업그레이드 시트에 costScale 열, `GameBalanceValidator.cs`, `BALANCE_IDLE.md` 골드 공식 설명.
