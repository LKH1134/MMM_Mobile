# 밸런스설계 — 에이전트 공유 공간 (방치형 강화 비용·골드 곡선 (로그형 진행))

방치형 강화 비용·골드 곡선 (로그형 진행)를 관리자 + 네 에이전트가 나눠 맡고, 여기서 현황·결과·요청을 주고받는다. 정의는 `.claude/agents/idle-*.md`.

| 이름 | 역할 | 산출물 | 모델 |
|---|---|---|---|
| `manager` | 관리자(메인): 할당·감시·정정·요청 배달·코드 적용·문서/DB 기록 | `현황/manager.md`, `문서.md` | Opus |
| `research` | 자료조사: 레전드 오브 슬라임·먼작귀 포켓 → 측정 가능한 원칙 P1~Pn | `조사.md` | Sonnet |
| `theory` | 이론: 실제 공식 기반 근사 모델 → 재현 → 수치안·구조안 | `이론.md`, `밸런스설계/theory/` | Opus |
| `verify` | 검증: 독립 재계산·코드 대조·조건·민감도 → 판정 | `검증.md` | Opus |
| `test` | 실측: 파이썬 시뮬 · 모든 수치에 출처 | `테스트.md`, `밸런스설계/verify/` | Sonnet |

## 흐름

기본 순서는 조사 → 이론 → 검증 → (관리자가 적용) → 테스트. 그 위에 **누구든 누구에게나 요청**한다(이론이 근거 필요 → research, 측정 필요 → test, 테스트가 차이 원인 → theory, 검증이 실측 필요 → test …). 넷 다 동시에 시작하고, 앞 단계 결과가 없으면 지금 있는 것으로 먼저 하고 가정을 적는다.

## 공유 규칙

- **한 파일 = 한 작성자.** `현황/<내이름>.md`와 내 산출물만 쓴다. 남의 파일은 읽기만
- **요청 확인:** 시작할 때 · 단계마다 · 끝내기 직전에 `python 밸런스설계/요청보기.py <내이름>`. 나에게 온 요청(관리자 것 먼저)을 하던 일보다 먼저
- **요청:** 내 파일 "요청"에 `- [ ] #번호 → 대상: 무엇 · 왜 · 받고 싶은 형태 (시각) [막힘|참고]` — `[참고]`는 가정 두고 계속, `[막힘]`은 할 게 없으면 반환에 `대기: 내이름#번호`
- **답:** 받은 쪽이 자기 파일 "받은 요청 처리"에 `- [x] 보낸이#번호 → 답 · 결과 경로 (시각)` (못 하면 `거절: 이유 · 대신 누구에게`)
- **정정 요청에 동의하지 않으면** 근거를 답에 적는다(무조건 따르지 않는다)
- **알림:** `[막힘]`을 올렸을 때, 산출물 초안이 나왔을 때, 끝날 때 SendMessage(to: "main") 한 줄
- **`문서.md`·코드·사용자 파일(DB 등)은 관리자만 쓴다**
- 시각은 **반드시 `date +%H:%M`**으로 확인해 적는다

## 관리자

- 할당은 `현황/manager.md` "요청"에 `manager#번호 → 대상`으로 적고 띄운다(끝난 에이전트는 SendMessage로 이어서)
- 산출물 수치는 원 기록으로 직접 다시 계산해 확인 → `검증: … 확인` 또는 정정 요청
- 받는 쪽이 끝났으면 깨워서 처리시키고, `대기:`로 끝난 에이전트는 답이 달리면 깨운다
- verify 통과안만 적용, 사용자 결정 전 구조 변경은 기본 꺼진 실험 플래그로만
- 같은 요청이 3번 넘게 오가거나 사용자 몫(목표·기준·구조)이면 멈추고 사용자에게 묻는다

## 현황 파일 형식

```
# <이름> 현황
지금: (하는 일 한 줄 | 끝: 결과 한 줄)

## 공유할 결과
- 경로 · 요약 · 시각

## 요청
- [ ] #1 → 대상: 내용 · 왜 · 받고 싶은 형태 (시각) [막힘|참고]

## 받은 요청 처리
- [x] 보낸이#번호 → 답 · 결과 경로 (시각)
```
